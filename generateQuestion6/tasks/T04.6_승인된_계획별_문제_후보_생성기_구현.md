## 구현 범위
1. Candidate Generator에는 승인 계획, ProblemSpec, 학교 문체 프로필만 전달하고 원문 전문은 제외한다.
2. 문제 본문, formalization, final_answer_claim, solution_steps, transformation_evidence를 분리한다.
3. 생성기의 답과 해설은 검증 전 주장값으로 표시한다.
4. 계획 필드 변경과 추가 범위 개념 도입을 서버 검증으로 차단한다.

## 테스트 우선 실행 순서
1. 첫 필수 테스트를 작성한다.
2. 테스트를 단독 실행해 의도한 정책 위반 또는 미구현 이유로 실패하는지 확인한다.
3. 해당 계약을 만족하는 최소 구현을 작성한다.
4. 같은 모듈의 골드·속성·통합 테스트를 실행한다.
5. 관련 전체 변형 계획 회귀 테스트와 정적 검사를 실행한다.

## 필수 테스트와 판정 기준
- [ ] **T04.6-GT1:** 후보의 formalization이 계획의 symbols·constraints·goal과 일치한다.
- [ ] **T04.6-GT2:** 문제 본문에 surface_blacklist 고위험 패턴이 나타나면 탈락한다.
- [ ] **T04.6-GT3:** 생성기가 계획 밖 개념을 추가하면 PLAN_DRIFT다.
- [ ] **T04.6-GT4:** final_answer_claim은 검증 상태 PASS를 자동 부여하지 않는다.
- [ ] **T04.6-GT5:** 통과 계획 수보다 많은 후보를 생성하지 않는다.

## 작업 완료 정의
- [ ] 필수 테스트와 관련 전체 회귀 테스트가 통과한다.
- [ ] 실패·탈락마다 구조화된 이유와 비교 증거가 남는다.
- [ ] 원문 전문과 주장 정답이 금지된 모델 역할에 유출되지 않는다.
- [ ] 미검증 또는 판단 불능 계획·후보를 통과시키지 않는다.
- [ ] 새 규칙·임계값·프롬프트 버전을 문서화한다.
- [ ] 구현 범위를 벗어난 기능을 추가하지 않았다.
