## 구현 범위
1. 원문 정답이 있어도 보지 않는 독립 풀이 요청을 만든다.
2. 풀이 단계를 SolutionGraph로 구조화하고 가능한 주장을 고정 검증한다.
3. 해 없음·다중 해·조건 모순·정의역 문제·모호성 상태를 구분한다.
4. source gate가 PASS일 때만 변형 계획 단계로 전이한다.

## 테스트 우선 실행 순서
1. 첫 필수 테스트를 작성하고 해당 테스트만 실행한다.
2. 의도한 이유로 실패하는지 확인한다.
3. 테스트를 통과시키는 최소 구현을 작성한다.
4. 모듈 전체 테스트와 관련 통합·보안 테스트를 실행한다.
5. 정적 검사 후 증거와 운영 문서를 갱신한다.

## 필수 테스트와 판정 기준
- [ ] **T02.5-GT1:** 정상 접선 문항은 검증된 해와 SolutionGraph를 반환한다.
- [ ] **T02.5-GT2:** 조건 하나가 빠진 다중 해 문항은 AMBIGUOUS_OR_MULTI_SOLUTION이다.
- [ ] **T02.5-GT3:** 모순 조건 문항은 UNSATISFIABLE_SOURCE다.
- [ ] **T02.5-GT4:** 원문 제공 답과 독립 풀이가 다르면 생성이 중단된다.
- [ ] **T02.5-GT5:** UNRESOLVED 원문이 계획 단계로 전이하지 못한다.

## 작업 완료 정의
- [ ] 위 테스트가 모두 통과한다.
- [ ] 실패 테스트가 구현 전 실제로 실패함을 확인했다.
- [ ] 실패·판단 불능 상태가 구조화된 코드로 기록된다.
- [ ] 관련 회귀·정적 검사가 통과한다.
- [ ] 로그에 비밀정보와 불필요한 원문 전체가 노출되지 않는다.
- [ ] 범위 밖 기능을 추가하지 않았다.
