## 구현 범위
1. 풀이기 입력에서 원문 정답·해설·변형 계획·생성기 주장 답을 제거한다.
2. 가능하면 다른 공급자 또는 다른 모델 정책으로 A/B를 배치한다.
3. 문자열이 아니라 정규화된 해집합과 핵심 풀이 노드를 비교한다.
4. 풀이 불일치 시 원인과 필요한 추가 고정 검사를 반환한다.

## 테스트 우선 실행 순서
1. 오류 또는 안전 경계를 검출하는 첫 테스트를 작성한다.
2. 구현 전 의도한 이유로 실패하는지 확인한다.
3. 테스트를 통과시키는 최소 검증·집계·컴파일 로직을 작성한다.
4. 골드·속성·통합 테스트를 실행한다.
5. false pass 회귀 세트와 관련 전체 테스트를 실행한다.

## 필수 테스트와 판정 기준
- [ ] **T05.3-CT1:** 캡처된 모든 풀이 요청에 금지 필드가 0개다.
- [ ] **T05.3-IT1:** 1/2, 0.5, sqrt(4)/4 답이 동치로 합의된다.
- [ ] **T05.3-IT2:** 같은 최종 답이지만 정의역·중간 단계가 충돌하면 합의로 처리하지 않는다.
- [ ] **T05.3-IT3:** 두 풀이가 다르면 SOLVER_DISAGREEMENT이고 자동 승인되지 않는다.
- [ ] **T05.3-IT4:** 공급자 하나가 실패해도 다른 풀이만으로 PASS하지 않는다.

## 작업 완료 정의
- [ ] 필수 테스트와 관련 안전 골드셋이 모두 통과한다.
- [ ] false pass를 만드는 알려진 경로가 0건이다.
- [ ] FAIL·UNRESOLVED·반례가 원인과 증거를 포함한다.
- [ ] 모델의 자신감 또는 다수결만으로 PASS하지 않는다.
- [ ] 결과가 버전과 trace를 포함해 재현 가능하다.
- [ ] 변경된 검증 범위와 한계를 문서화했다.
