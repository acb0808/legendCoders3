## 구현 범위
1. 후보 본문, 최종 답, 해설, 루브릭, 변형 차원을 동일한 구조로 비교한다.
2. 고정 검사·샌드박스·블라인드 풀이·반례·비복제성 증거를 요약하고 상세 토글을 제공한다.
3. 샌드박스 코드는 고급 상세에서 읽기 전용으로 표시한다.
4. 반려 사유 코드를 필수로 받고 승인·반려 후 상태를 즉시 갱신한다.

## 테스트 우선 실행 순서
1. API 계약 또는 사용자 행동 테스트를 먼저 작성한다.
2. 구현 전 테스트가 의도한 이유로 실패하는지 확인한다.
3. 필요한 최소 API·상태·UI를 구현한다.
4. 단위·통합·브라우저 테스트를 실행한다.
5. 관련 백엔드 상태·보안·접근성 회귀 테스트를 실행한다.

## 필수 테스트와 판정 기준
- [ ] **T06.4-UT1:** 검증을 통과하지 않은 후보는 카드 목록에 나타나지 않는다.
- [ ] **T06.4-UT2:** 문제·답·해설·부분점수·변형 설명·증거 필드 누락 시 승인 버튼이 비활성화된다.
- [ ] **T06.4-UT3:** 반려 사유 없이 반려할 수 없다.
- [ ] **T06.4-UT4:** 승인 후 같은 후보를 다시 승인해 중복 이벤트를 만들지 않는다.
- [ ] **T06.4-UT5:** 코드·긴 증거를 접어도 핵심 PASS·FAIL·UNRESOLVED 상태는 항상 보인다.

## 작업 완료 정의
- [ ] 필수 테스트와 관련 E2E가 모두 통과한다.
- [ ] 미검증 후보 또는 민감 내부 정보가 사용자에게 노출되지 않는다.
- [ ] 새로고침·중단·재시작 후 상태가 일관된다.
- [ ] 오류 메시지가 오류 코드·원인·가능한 조치를 포함한다.
- [ ] 학생 기능이나 자동 게시 경로를 추가하지 않았다.
- [ ] API·화면 동작과 운영 주의사항을 문서화했다.
