## 구현 범위
1. 각 규칙에 rule_id, preconditions, changed_dimensions, construction_template, difficulty_delta, verifier_recipe, conflicts를 정의한다.
2. 직선 직접식↔두 점·기울기·교점, 원 직접식↔중심·반지름·자취, 접선↔거리·판별식 규칙을 구현한다.
3. 질문 역전, 조건 위상, 변수 역할, 보조 구성, 이동·대칭 규칙을 추가한다.
4. 규칙 조합 전제와 상충 규칙을 결정론적으로 검사한다.

## 테스트 우선 실행 순서
1. 첫 필수 테스트를 작성한다.
2. 테스트를 단독 실행해 의도한 정책 위반 또는 미구현 이유로 실패하는지 확인한다.
3. 해당 계약을 만족하는 최소 구현을 작성한다.
4. 같은 모듈의 골드·속성·통합 테스트를 실행한다.
5. 관련 전체 변형 계획 회귀 테스트와 정적 검사를 실행한다.

## 필수 테스트와 판정 기준
- [ ] **T04.1-UT1:** 원이 없는 ProblemSpec에는 circle 변형 규칙이 적용되지 않는다.
- [ ] **T04.1-UT2:** 접선 규칙은 반지름과 직선 또는 동치 구성을 요구한다.
- [ ] **T04.1-UT3:** 상충 규칙 조합은 RULE_CONFLICT로 거부된다.
- [ ] **T04.1-UT4:** 각 규칙은 최소 하나의 실행 가능한 verifier_recipe를 가진다.
- [ ] **T04.1-UT5:** 규칙 카탈로그의 모든 개념 ID가 ScopeProfile 어휘에 존재한다.
