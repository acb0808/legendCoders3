## 구현 범위
1. 보존 개념, 변경 차원, 규칙 ID, 구성 청사진, 예상 풀이 그래프, 검증 계약을 정의한다.
2. CandidateProblem의 문제 본문과 기계 형식화·주장 답을 분리한다.
3. ValidationEvidence에 PASS·FAIL·UNRESOLVED, 실행 증거, 반례, 도구·코드 버전을 정의한다.
4. critical 검사 하나가 FAIL 또는 UNRESOLVED면 자동 통과할 수 없게 한다.

## 테스트 우선 실행 순서
1. 아래 첫 필수 테스트를 작성한다.
2. 해당 테스트만 실행해 의도한 이유로 실패하는지 확인한다.
3. 테스트를 통과시키는 최소 구현을 작성한다.
4. 해당 테스트와 같은 모듈의 전체 테스트를 실행한다.
5. 정적 검사와 관련 통합 테스트를 실행한다.
6. 코드·테스트·문서가 완료 게이트를 만족할 때만 리뷰를 요청한다.

## 필수 테스트와 판정 기준
- [ ] **T01.3-UT1:** 변경 차원이 4개 미만이면 PLAN_CHANGE_DIMENSION_SHORTAGE다.
- [ ] **T01.3-UT2:** 구조적 변경이 2개 미만이면 계획을 거부한다.
- [ ] **T01.3-UT3:** critical UNRESOLVED가 있는 증거 집합은 PASS로 집계되지 않는다.
- [ ] **T01.3-UT4:** 반례가 있는 검사는 상태가 PASS일 수 없다.
- [ ] **T01.3-UT5:** 직렬화 결과에 코드·입력·도구 버전 provenance가 남는다.

## 작업 완료 정의
- [ ] 위 필수 테스트가 모두 통과한다.
- [ ] 실패 테스트가 실제 결함을 검출한다는 것을 먼저 확인했다.
- [ ] 새 오류 상태가 구조화된 코드와 감사 로그로 남는다.
