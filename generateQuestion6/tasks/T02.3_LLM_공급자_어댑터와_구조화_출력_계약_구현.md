## 구현 범위
1. generate_structured와 role policy 인터페이스를 정의한다.
2. 모델명 대신 source_analyzer, generator, blind_solver, critic 역할 정책을 설정에 매핑한다.
3. 응답을 서버에서 Pydantic 재검증하고 빈 응답·잘린 JSON·누락 필드를 구분한다.
4. 형식 복구 1회와 다른 공급자 폴백 1회를 상태 머신 정책에 연결한다.

## 테스트 우선 실행 순서
1. 첫 필수 테스트를 작성하고 해당 테스트만 실행한다.
2. 의도한 이유로 실패하는지 확인한다.
3. 테스트를 통과시키는 최소 구현을 작성한다.
4. 모듈 전체 테스트와 관련 통합·보안 테스트를 실행한다.
5. 정적 검사 후 증거와 운영 문서를 갱신한다.

## 필수 테스트와 판정 기준
- [ ] **T02.3-CT1:** 유효 JSON은 해당 Pydantic 모델로 파싱된다.
- [ ] **T02.3-CT2:** 빈 응답·잘린 JSON·추가 필드가 각각 구조화된 오류가 된다.
- [ ] **T02.3-CT3:** 복구 1회 실패 후 폴백 1회만 호출된다.
- [ ] **T02.3-CT4:** 공급자 로그에 키·전체 민감 프롬프트가 남지 않는다.
- [ ] **T02.3-CT5:** 역할 정책 변경은 비즈니스 코드 수정 없이 설정만 바꾼다.
