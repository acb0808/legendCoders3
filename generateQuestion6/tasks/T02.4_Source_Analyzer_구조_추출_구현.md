## 구현 범위
1. 정규화 블록과 ScopeProfile만 입력으로 사용한다.
2. 명시 조건과 암묵 조건, 정의역, 답 형태, 핵심·보조 개념을 구분한다.
3. 확정하지 못한 가정은 unresolved_assumptions로 반환하고 자동 생성 경로를 막는다.
4. 추출 결과를 도메인 불변식과 골드 fixture에 대조한다.

## 테스트 우선 실행 순서
1. 첫 필수 테스트를 작성하고 해당 테스트만 실행한다.
2. 의도한 이유로 실패하는지 확인한다.
3. 테스트를 통과시키는 최소 구현을 작성한다.
4. 모듈 전체 테스트와 관련 통합·보안 테스트를 실행한다.
5. 정적 검사 후 증거와 운영 문서를 갱신한다.

## 필수 테스트와 판정 기준
- [ ] **T02.4-GT1:** 원·직선 접선 문항에서 중심·반지름·직선·매개변수·목표가 정확히 추출된다.
- [ ] **T02.4-GT2:** 분모·근호·부호의 암묵 정의역이 누락되면 골드 비교가 실패한다.
- [ ] **T02.4-GT3:** 범위 밖 개념을 핵심 개념으로 추출하면 SCOPE_VIOLATION이다.
- [ ] **T02.4-GT4:** 모호한 자연어는 추측하지 않고 unresolved_assumptions를 생성한다.
- [ ] **T02.4-GT5:** 동일 입력 재실행 시 스키마와 핵심 필드가 안정적이다.

## 작업 완료 정의
- [ ] 위 테스트가 모두 통과한다.
- [ ] 실패 테스트가 구현 전 실제로 실패함을 확인했다.
- [ ] 실패·판단 불능 상태가 구조화된 코드로 기록된다.
- [ ] 관련 회귀·정적 검사가 통과한다.
- [ ] 로그에 비밀정보와 불필요한 원문 전체가 노출되지 않는다.
- [ ] 범위 밖 기능을 추가하지 않았다.
